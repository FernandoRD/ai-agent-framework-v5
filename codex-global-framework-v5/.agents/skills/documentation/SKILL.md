# Documentation

Ground the document in the actual project, audience, supported versions, and
verified commands. Preserve established terminology and structure when editing
existing documentation.

Organize around user outcomes and decisions. Include prerequisites, safe steps,
validation, failure handling, and rollback only when relevant. Mark examples,
placeholders, assumptions, and destructive commands clearly. Do not present
untested commands or inferred system behavior as verified facts.

Check links, file paths, command syntax, version claims, and consistency with
the implementation. Keep the result concise enough to be maintained.
