# RAG ingestion

This optional helper gathers candidates from explicitly allowlisted Git and Jira sources. It is not scheduled and never changes the installed package. Copy `rag_sources.example.json` to a project-local location, replace every example value, then select an explicit writable data directory outside this package.

```bash
python3 scripts/rag_ingest.py validate --config /srv/zabbix-rag/sources.json
python3 scripts/rag_ingest.py sync --config /srv/zabbix-rag/sources.json --data-root /srv/zabbix-rag/data
python3 scripts/rag_ingest.py promote --data-root /srv/zabbix-rag/data --candidate SOURCE-HASH --approve
python3 scripts/rag_ingest.py index --data-root /srv/zabbix-rag/data
```

Git requires an exact `repo`, `ref`, and repository-relative `path`, each repeated in its corresponding allowlist. Each Git source must select exactly one eligible text document; zero or multiple matches fail that source before any blob is read. Add one source per document to ingest multiple documents, as shown in the example. Repositories may use only `https://`, `ssh://`, or `git@host:path` with a valid hostname; local paths, `file://`, `ext::`, options, URL credentials, queries, and fragments are rejected. On POSIX, Git clones with `--no-checkout --filter=blob:none` and every blob-reading Git subprocess has a 2 MB `RLIMIT_FSIZE`, so lazy/promisor retrieval cannot grow its on-disk pack beyond that boundary. Platforms without that enforceable POSIX limit refuse remote Git sync rather than claiming an equivalent safety boundary. Git otherwise runs with an isolated environment that permits only HTTPS/SSH and disables `file` and `ext` protocols, has a fixed subprocess timeout, rejects trees with more than 10,000 entries, and checks the selected blob's declared size before reading it. The stored provenance is the fetched commit. Jira requires a credential-free HTTPS URL with a valid hostname, an exact allowlisted base URL/project/status/JQL, bounded result and timeout settings, and a token only through the configured environment-variable name. Authenticated Jira requests reject redirects, so a token is never forwarded to another origin. Reads and issue processing use a source-wide monotonic deadline as well as the socket timeout; a misbehaving single blocking socket read can still overrun that deadline by up to its configured socket timeout because the standard library cannot interrupt that read safely. The utility never prints tokens.

Sync redacts known secret forms again immediately before every write to `raw/` and `candidates/`; it does not promote material, including Git content. This conservative best-effort filter covers case-insensitive common secret names (including `AWS_SECRET_ACCESS_KEY`, database/connection URLs, cookies and session values), URL credentials, authorization headers and Token/JWT/Bearer/Basic values, and complete private-key blocks. Documents containing incomplete private-key material are rejected before content is persisted. A failed source is reported with a sanitized error while remaining configured sources continue. It is not a complete DLP system: review candidates for residual sensitive data, accuracy, access restrictions, and version compatibility before promotion. Promotion always needs both a named candidate and `--approve`. The resulting `index/catalog.json` contains only explicitly approved candidates.
